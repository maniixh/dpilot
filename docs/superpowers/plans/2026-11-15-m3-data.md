# M3 Data Browsing & SQL Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browse, filter and edit table rows in a virtualised grid, and run SQL scripts in a CodeMirror editor with cancel, history and saved queries, on MySQL, MariaDB and Postgres.

**Architecture:** Pure SQL tools (tokenizer, splitter, classifier) live in `@dpilot/shared` so server and browser agree. The server adds a per-engine `DataAdapter` (built from dialect-aware query builders; lossless text casts) beside the M2 `ExplorerAdapter`, and a `QueryService` that runs split scripts statement-by-statement on a pinned session per editor tab. The store gains history, saved queries and a read-only flag. The web app adds a grid route (TanStack Table + Virtual) and a lazy editor route (CodeMirror 6).

**Tech Stack:** Bun 1.4.4 (`Bun.SQL` with `bigint: true`, `.values()`, `reserve()`, `begin()`), Hono 4, Zod 4, React 19, TanStack Query 5 / Table 8 / Virtual 3, CodeMirror 6 (`codemirror`, `@codemirror/lang-sql`), wouter 3.

**Spec:** `docs/superpowers/specs/2026-11-15-m3-data-design.md` — read it before any task; it fixes contracts, limits, error codes and copy this plan does not repeat.

## Global Constraints

- Strict types; Zod at every boundary (request bodies, query strings, stored rows, driver rows). No `any`; no unchecked `as` on external data.
- Anything `apps/server/src/app.ts` imports (transitively) must not import `node:*`, `bun:*` or use Bun globals: interfaces and error classes live in `types.ts` files; Bun-backed implementations (`bun-sql.ts`, `bun-session.ts`, store repositories using `bun:sqlite`) are wired in `cli/run.ts` and `testing/build-app.ts`.
- Values are never interpolated into SQL — always bound parameters. Identifiers go only through `quoteIdent(dialect, name)` and must first be matched against `TableMeta` columns (or catalog results). Postgres type casts use type text from the catalog only.
- Primary-key values are `RowKey = Record<string, string>` (exact text), never JS numbers.
- Limits (spec): page ≤ 1000 rows; editor result ≤ 10 000 rows (default 1000); ≤ 100 outcomes kept per run (first 50 + last 50); script ≤ 16 MB; cell upload ≤ 16 MB; history 5000 rows, SQL stored redacted and ≤ 100 KB; saved query ≤ 1 MB; ≤ 10 editor tabs; ≤ 500 keys per delete.
- Data dir `~/.dpilot`; store `~/.dpilot/dpilot.db`; migrations are append-only (`store/database.ts` `MIGRATIONS`).
- Biome: `lineWidth: 100`, 2-space indent, double quotes. Check with `powershell -File <session>\files\m2\biome.ps1` (2 `index.css` Tailwind errors are expected noise) and keep lines ≤ 100.
- Tools via `bunx`. Server typecheck: `bunx tsc --noEmit -p tsconfig.json` in `apps\server`; web: same plus `-p tsconfig.test.json` in `apps\web`; shared: `bunx tsc --noEmit` in `packages\shared`. Tests: `bun test` at repo root. Web build: `bunx vite build` in `apps\web`.
- Integration tests (`DPILOT_INTEGRATION=1`) create their own `it-*` containers. Never stop, remove or change `dpilot-test-mysql` or `dpilot-test-dpilot`.
- Commits: `git -c user.name="Manish Gupta" -c user.email=manishguptacpn@gmail.com commit -m "..."`, Conventional Commits, **no Co-authored-by or any other trailer**. One commit per task on branch `m3-data`. Never push.
- UI copy: sentence case, plain verbs; reuse `buttonClass`, `Field`, `inputClass`, `Facts`, `ErrorLine`, `CopyButton`, tokens `ink/chart/slate/rule/down/flag`, IBM Plex. Destructive confirmations use native `<dialog>`.
- Web components are verified by real-browser screenshots (no DOM test env); pure logic beside them (`*-model.ts`) is unit-tested with `bun test`.

## Review Focus

1. A Postgres `WITH gone AS (DELETE FROM t RETURNING *) SELECT * FROM gone`, a MySQL `/*!50000 DROP TABLE t */`, or `SELECT … INTO OUTFILE` on a read-only connection must be refused before anything runs — Task 2 tests `classifies a data-modifying CTE as write`, `treats executable comments as code`, `classifies INTO OUTFILE as unknown`; Task 8 test `refuses a data-modifying CTE on a read-only connection`.
2. Editing a row whose key is a BIGINT above 2^53 (e.g. `9007199254740993` next to `9007199254740992`) must change only that row — Task 6 integration test `updates only the row with a key above 2^53`; Task 4 test `builds the key predicate from text values`.
3. DATETIME(6) / timestamp microseconds and Postgres arrays shown in the grid and saved back unchanged must not alter the stored value — Task 6 integration test `round-trips microseconds and arrays through update`.
4. Cancel pressed during the third statement of a MySQL script must stop that statement, run nothing after it, and not cancel the next run on the tab — Task 8 tests `cancel stops the in-flight statement and skips the rest` and `a cancel that settles late does not touch the next run`.
5. Table, schema and column names with quotes, backticks, dots, spaces or unicode must browse and edit correctly — Task 4 test `quotes identifiers containing the quote character`; Task 9 test `tableHref round-trips names with slashes and quotes`.

### Task 2: Shared SQL tools

**Files:**
- Create: `packages/shared/src/sql/tokens.ts`, `split.ts`, `classify.ts`, `redact.ts`, `sql.test.ts`; export from `index.ts`.

**Interfaces:**
- Produces:
  - `tokenize(text: string, dialect: Dialect): Token[]`, `Token = { kind: "word" | "ident" | "string" | "number" | "punct" | "comment" | "space"; text: string; start: number; end: number }`. Handles `'…'` with `''` (and `\'` on MySQL), `"…"` (ident on Postgres, string on MySQL), backticks (MySQL ident), `-- `, `#` (MySQL), `/* */` (nested on Postgres), `$tag$…$tag$` (Postgres), `E'…'`. MySQL `/*! … */`, `/*!NNNNN … */`, `/*M! … */` are NOT comments: their inner text is tokenized as code.
  - `splitStatements(text: string, dialect: Dialect): { text: string; start: number; end: number }[]` — splits on `;` outside quotes/comments; MySQL `DELIMITER xx` lines change the delimiter and are not emitted; empty/comment-only statements dropped; `text` is trimmed, `start`/`end` are offsets into the input of the trimmed text.
  - `statementAt(statements, offset: number)` → the statement containing `offset`, else the nearest one ending before it, else null.
  - `classifyStatement(text, dialect): "read" | "write" | "ddl" | "transaction" | "session" | "unknown"` — rules in the spec's SQL tools paragraph (conservative; `read` only by allow-list).
  - `destructiveReasons(text, dialect): string[]` — copy: `"Drops <object kind>"`, `"Empties the table (TRUNCATE)"`, `"Drops part of a table (ALTER … DROP)"`, `"DELETE without WHERE affects every row"`, `"UPDATE without WHERE affects every row"`, `"Can't tell what this statement changes"` (unknown + risky token).
  - `redactSql(text): string` — replaces string literals following `IDENTIFIED BY`, `PASSWORD`, `IDENTIFIED WITH … BY` with `'***'`.
  - `explainSql(dialect, text): string` — MySQL `EXPLAIN <text>`, Postgres `EXPLAIN (FORMAT TEXT) <text>`; never `ANALYZE`.

- [ ] **Step 1: Write failing tests** (`sql.test.ts`), one `test` each:
  - `splits on semicolons outside quotes and comments`: `"SELECT 'a;b'; -- x;\nSELECT 2"` → 2 statements, first text `SELECT 'a;b'`.
  - `keeps dollar-quoted bodies whole`: Postgres `CREATE FUNCTION f() RETURNS int AS $$ SELECT 1; $$ LANGUAGE sql; SELECT 2` → 2.
  - `honours DELIMITER`: MySQL `"DELIMITER //\nCREATE PROCEDURE p() BEGIN SELECT 1; END//\nDELIMITER ;\nSELECT 2;"` → 2 statements, first ends with `END`.
  - `reports offsets into the original text` and `statementAt picks the statement under the cursor`.
  - `classifies a data-modifying CTE as write`: Postgres `WITH g AS (DELETE FROM t RETURNING *) SELECT * FROM g` → not `read`; `destructiveReasons` contains the DELETE reason.
  - `treats executable comments as code`: MySQL `/*!50000 DROP TABLE t */` → `ddl`, reasons contain `"Drops table"`; while `/* DROP TABLE t */ SELECT 1` → `read`.
  - `classifies INTO OUTFILE as unknown`: `SELECT * FROM t INTO OUTFILE '/tmp/x'` → `unknown`; also `SELECT * INTO copy FROM t` (Postgres) → not `read`; `SELECT … FOR UPDATE` → not `read`; `EXPLAIN ANALYZE DELETE FROM t` → not `read`.
  - `reads`: `SELECT`, `WITH x AS (SELECT 1) SELECT * FROM x`, `SHOW TABLES`, `EXPLAIN SELECT 1`, `VALUES (1)` → `read`; `BEGIN`, `COMMIT`, `START TRANSACTION READ WRITE` → `transaction`; `SET x = 1`, `USE db` → `session`.
  - `flags DELETE and UPDATE without WHERE`: `DELETE FROM t` and `UPDATE t SET a = (SELECT 1 WHERE true)` → reason; `DELETE FROM t WHERE id = 1` → `[]`; `TRUNCATE t` and `ALTER TABLE t DROP COLUMN c` → reasons; quoted `'DROP TABLE'` inside a string → `[]`.
  - `redacts passwords`: `CREATE USER u IDENTIFIED BY 'secret'` → contains `'***'`, not `secret`; Postgres `ALTER ROLE u PASSWORD 'x'` likewise.

### Task 7: Query sessions

**Files:**

**Interfaces:**
